How to edit EXIF data

  1. Choose a photo (JPEG, PNG or WebP) or drop it on the box. The list under "Found in this photo" shows what it reveals: GPS position, date, camera, serial numbers, a thumbnail, editing software.
  2. Fill Copyright and credit. Creator, Credit line and Copyright notice are what Google Images displays. Add a licence page URL and a contact or shop URL to make the photo eligible for the Licensable badge.
  3. Change or clear any other field. Empty a field to delete it. Tick Remove location to drop every GPS tag, or type new coordinates in decimal degrees.
  4. Save and download. The file keeps its format and its pixels; the name gets -edited. Load several photos and use Copyright to all photos to stamp the same credit on every one and get a ZIP.

What Google Images reads from a photo

Google has said EXIF camera data is not a ranking factor. What it does use is IPTC photo metadata, the standard newsrooms and stock agencies use for credits. Google Images shows the Creator, Credit Line and Copyright Notice with the image, and uses Web Statement of Rights and Licensor URL for the Licensable badge (Google Search Central, IPTC). This editor writes them as XMP, the modern home for IPTC fields, and removes any old IPTC IIM block so two copies cannot disagree.

Why this editor does not lose quality

A photo file is a series of blocks: the compressed image, then separate blocks for EXIF, XMP, IPTC and the colour profile. This editor reads those blocks and rebuilds only the metadata ones. The compressed image data is copied byte for byte, so the picture is identical, not just "similar". Online editors that load the photo into a canvas and export it again recompress it, drop the colour profile and lose every field they do not rewrite.

  • JPEG: EXIF and XMP go in APP1 segments after the JFIF header; old IPTC (APP13) is replaced by the XMP when you edit copyright.
  • PNG: EXIF goes in an eXIf chunk and XMP in an iTXt chunk, both before the image data.
  • WebP: EXIF and XMP chunks are added at the end and the extended header flags are set, as the WebP container specification requires.
  • Kept as they are: byte order, the maker note, the thumbnail (unless you remove it), the colour profile and every tag you did not edit. Other XMP, such as Lightroom edit history, is replaced when you change the copyright fields.

Frequently asked questions

What is EXIF data?

EXIF (Exchangeable image file format) is data a camera or phone writes inside a photo: make and model, lens, shutter speed, aperture, ISO, the date and time taken, orientation, often the GPS position and a small preview thumbnail. It sits in its own block next to the image data, so you can read or change it without touching the pixels. The sample photo on this page holds 8 kinds of personal data, including a GPS position at Bukit Besi, Terengganu (4.75833, 103.195).

Does EXIF data help SEO or Google rankings?

No. Google has said EXIF is not used as a ranking factor, and camera settings or GPS tags will not lift a page. What Google Images does read is IPTC photo metadata: it shows the Creator, Credit Line and Copyright Notice next to an image, and the Web Statement of Rights and Licensor URL fields can add a Licensable badge with a link to where the image can be licensed. Rankings still come from the page: alt text, file name, captions, surrounding text and fast loading.

How do I get the Licensable badge in Google Images?

Give Google a licence link in one of two ways. Embed it in the file: fill Web Statement of Rights (the page that explains your licence) and Licensor URL (where to get a licence) in this editor and download. Or add ImageObject structured data with license and acquireLicensePage to the page that shows the image. Using both is safest, because many CMS and CDN resizers delete embedded metadata from the copies they serve. Google decides when to show the badge; the fields make an image eligible.

Does editing EXIF reduce image quality?

Not with this editor. It rewrites only the metadata blocks (EXIF, XMP and IPTC) and copies the compressed image data byte for byte, so nothing is decoded or recompressed. The file size changes only by the size of the metadata you add or remove. Editors that redraw the photo on a canvas and save it again lose quality and usually drop the colour profile too.

How do I change the date a photo was taken?

Load the photo, set Date taken under Camera and date, and download. The editor writes DateTimeOriginal and CreateDate in the EXIF format YYYY:MM:DD HH:MM:SS, for example 2026:08:31 07:42:10, which is what Google Photos, Windows and most galleries use to sort pictures. The file's modified date on your computer is separate and changes when you save the download.

How do I add or remove the GPS location of a photo?

To remove it, tick Remove location and download: every GPS tag is deleted while the rest stays. To add or correct it, type latitude and longitude in decimal degrees, such as 3.1390 and 101.6869 for Kuala Lumpur, and an altitude in metres if you want. The editor converts them to the degrees, minutes and seconds EXIF stores, with N/S and E/W references and the WGS-84 datum.

Are my photos uploaded to a server?

No. Reading, editing and saving happen in your browser with JavaScript, so photos never leave your device, and the page works offline after one visit. Only the copyright details you type can be kept, in the page link after #, so you can bookmark them and reuse them. JPEG, PNG and WebP up to 50 MB each are supported; HEIC must be converted to JPEG first.
