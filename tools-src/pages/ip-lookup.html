How the lookup works

  1. Your IP: the page asks this site's own Cloudflare server which address your request came from (/cdn-cgi/trace), so no outside IP service sees you.
  2. Owner: the address is checked against the official record of the regional internet registry that issued it, over RDAP (RFC 9083). Malaysian addresses are issued by APNIC.
  3. Reverse DNS: the PTR record is read from Cloudflare's public DNS-over-HTTPS resolver. A domain you type is first resolved to its IPv4 and IPv6 addresses the same way.
  4. Type: the address is compared with the IANA special-purpose registries to tell public, private, carrier-grade NAT, loopback, documentation and multicast addresses apart.

IP address formats

  • Decimal: an IPv4 address is a 32-bit number; 8.8.8.8 = {{I_DEC}}.
  • Binary: 8.8.8.8 = {{I_BIN}}, which is how subnet masks are worked out.
  • IPv6 short form: written per RFC 5952, lowercase with the longest run of zero groups as ::, so 2001:0db8:0000:0000:0000:0000:0000:0001 is 2001:db8::1.
  • Reverse DNS name: 2001:db8::1 is looked up as {{I_V6REV}}.

Disclaimer: registry records are supplied by the address holder and can be out of date; they show who holds a block, not who used an address at a given moment. Do not use an IP lookup to identify or confront a person. Addresses with leading zeros (such as 010.1.1.1) are refused because some systems read them as octal.
