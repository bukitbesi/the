Unused CSS Remover

An unused CSS remover deletes the style rules no element on your pages uses, so the browser downloads and parses less CSS before it can show the page. Add your CSS and your pages (paste them, upload files, load URLs or capture a live page), and the tool tests every selector against them.     How to remove unused CSS

    1. Add your CSS: paste it, upload files, or let the tool load the stylesheets of the pages you add.
    2. Add every type of page your CSS serves: home, article, product, category, search, contact. A rule used only on one page type is removed if that page is missing.
    3. Add what JavaScript changes: capture pages with menus and popups open, add the scripts that add classes, or keep the JavaScript states safelist on.
    4. Check the report, copy or download the cleaned CSS, and test it on a copy of your site before replacing the original.

    Exact or keyword matching?

    Matching modes
    ModeHow it decidesBest for
    ExactBuilds each page like a browser and runs every selector with querySelector.     KeywordKeeps a selector when every class, id and tag name in it appears anywhere in your pages or scripts, as PurgeCSS does. Structure such as .a > .b is not checked.Templates, PHP or Blogger theme code and pages built by JavaScript. Safest.

    In exact mode, class names that appear in the JavaScript you add also count as used, so styles for states that scripts switch on are kept.

    What else it removes, and what it never touches

    • Selector lists: in .btn-danger, .alert-danger { … } only the unused names are removed; the rule stays if one is used.
    • @media, @supports and @container blocks are cleaned inside and dropped when nothing is left.
    • @keyframes are removed when no remaining rule names them in animation.
    • @font-face rules are removed when no remaining rule uses that font family, which also stops the browser downloading the font.
    • CSS variables (optional) are removed when nothing reads them with var(), in the CSS, inline styles or scripts you add.
    • Always kept: *, html, body, :root, ::selection, scrollbar styles, @import, @layer order, @property, @page, nested rules and licence comments.

    Removing unused CSS from a Blogger theme

    1. Back up the theme: Theme → ⋮ → Backup.
    2. Capture each page type with the bookmarklet: home page, a post, a static page, a label page (/search/label/…) and a search result (/search?q=…). Open the mobile menu and any popups before capturing. Blogger blogs block other sites from reading them, so URL loading needs the capture instead.
    3. Use the theme's own CSS: in Edit HTML, copy the CSS inside <b:skin><![CDATA[ … ]]> and paste it as the stylesheet, replacing the captured inline CSS. That keeps Theme Designer variables such as $(body.text.color) instead of their current values.
    4. Turn on the Blogger widgets safelist if you sometimes add gadgets that are not on the captured pages.
    5. Paste back: keep the Variable definitions comment block at the top of <b:skin> exactly as it was, and paste the cleaned CSS below it.

    Blogger also loads its own widget stylesheet. With b:css='false' on the <html> tag it is not loaded, but then every widget needs styles in your theme, so only change it if your theme was built for that.

    WordPress

    Clean your theme or child theme stylesheet, with pages captured for each template (front page, single post, page, archive, search, 404, and WooCommerce pages if you use it). Turn on the WordPress safelist so block-editor classes such as alignwide and has-text-align-center stay. Plugin stylesheets are best handled by a performance plugin's "remove unused CSS" feature, because they change with every plugin update.
