How to minify CSS

  1. Paste your CSS into the left box, upload a .css file, or drop the file onto the box.
  2. Choose options. The defaults are safe for any valid CSS. Untick "Keep /*! licence comments" only if you have checked the licence allows it.
  3. Copy or download the result. Downloads are named yourfile.min.css.
  4. Keep the original for editing and publish only the minified copy. To edit a minified file later, switch to Beautify.

What it never changes

Aggressive minifiers save a few extra bytes by rewriting values, and that is where broken layouts come from. This tool reads your CSS as tokens, the way the CSS Syntax specification describes, and leaves alone anything where a shorter form could behave differently:

  • Spaces around + and - in calc(): calc(100% - 2rem) stops working as calc(100%-2rem).
  • Units on 0 where they matter: 0s in transitions, 0%, flex: 1 1 0px and anything inside a function keep their unit.
  • Custom properties such as --brand: #FFFFFF keep their value exactly, because they are only resolved where they are used. An empty --x: ; keeps its space, which older Safari versions need.
  • Strings and url(): content text, font names and data URIs are copied byte for byte.
  • Selectors: div :first-child keeps its space (it means something different from div:first-child), and an ID such as #aabbcc is never shortened like a colour.
  • Rule order and shorthands are never merged or reordered, so the cascade stays the same.

Tested on Bootstrap 5.3.3: the full stylesheet goes from 281,046 to 232,701 bytes, and a second, independent minifier (Lightning CSS) parses the original and the result into identical rules.

Minify vs gzip and Brotli

Your web host usually compresses CSS with gzip or Brotli while sending it. Minifying first still helps, because compression cannot remove comments or whitespace, only encode them more efficiently.

The browser also parses the uncompressed size, so a smaller file is quicker to process on low-end phones. For the biggest win, remove CSS your pages do not use, then minify what is left.

Using minified CSS on Blogger and WordPress

Blogger

Go to Theme → Edit HTML and find <b:skin><![CDATA[. Keep the Variable definitions comment at the top unchanged, because Blogger reads its <Variable> tags for the Theme Designer. Minify only the CSS after it and paste the result back before ]]></b:skin>. Blogger placeholders such as $(body.text.color) pass through unchanged.

WordPress

In a child theme, keep the header comment (Theme Name:, Template:) at the top of style.css, since WordPress reads it to recognise the theme, and paste the minified CSS below it. For Appearance → Customize → Additional CSS, keep a readable copy elsewhere: minified CSS saved there is hard to edit later. Caching plugins that minify CSS do the same job automatically, so do not minify twice.

Tip: run PageSpeed Insights before and after. If "Minify CSS" is no longer listed under opportunities, the change worked.
